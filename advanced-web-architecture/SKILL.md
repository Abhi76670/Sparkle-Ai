# Advanced Web Architecture
Inspect the existing project, framework, routes, dependencies, assets, conventions and current features before coding. Do not replace working architecture without a concrete reason. Plan users/jobs-to-be-done, pages/routes, reusable components, data model, state boundaries, API boundaries, loading/empty/error/success states and acceptance criteria.
Build cohesive, subject-specific products with strong hierarchy, purposeful typography, consistent spacing, polished navigation, meaningful interactions, accessible labels/focus states, realistic content and complete flows. Avoid generic templates, lorem ipsum, dead buttons, fake integrations and decorative controls that do nothing. Implement every visible primary action or clearly label unavailable functionality.
Separate UI, domain logic, API clients and persistence. Prefer existing dependencies. Add validation, useful errors, loading/empty states, retries and success feedback. Preserve existing features/data. Document assumptions and external setup.
